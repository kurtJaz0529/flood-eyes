# 3 分钟路演脚本 · 慧眼识灾

> 目标：让评委在 180 秒内记住三件事 —— **痛点真、技术实、能落地**。
> 建议 1 人主讲 + 1 人操作电脑，讲解与演示严格同步。
>
> **演示用桌面版更稳**：双击 `慧眼识灾.exe` 即可，会自动打开无地址栏的应用窗口，
> 后续页签操作与本文完全一致（详见 `docs/desktop_app.md`）。
> 首次启动约 20 秒，务必**提前打开并停在首页**，不要现场等启动。

---

## 0:00–0:20 开场（抛问题，不要念 PPT）

**说**：
"各位评委好。2023 年华北特大暴雨，一个县的应急指挥部要等多久，才能知道'到底哪几个乡镇被淹了、淹了多少平方公里'？

答案是：**1 到 3 天**。

因为今天主流做法还是人盯着卫星图一张张看、一笔笔圈。等圈完，黄金 72 小时救援期已经过去了大半。

我们做的系统叫**慧眼识灾**，它把这件事从**几天**压缩到**分钟级**。"

**屏幕**：停在系统首页（三个页签清晰可见）。

---

## 0:20–0:50 一键识别（核心演示，全程真跑）

**操作**：
1. 页签①，示例样本选 **【真实】2020·江西鄱阳湖特大洪水**；
2. 点击 **🚀 开始识别**。

**说**：
"这是一景**真实**的 Sentinel-2 卫星影像——2020 年 7 月鄱阳湖特大洪水，不是合成数据，数据来源和景号都能在清单里查到。点一下。"

**等结果出来（约 1 秒）后**：
"**1 秒**。系统自动完成了：波段还原 → NDWI 水体指数 → 阈值分割 → 形态学去噪 → 连通域过滤 → 面积换算。

屏幕上青色就是识别出的洪水淹没范围，红线是边界。右边这张卡片：**淹没面积 154 平方公里，占影像 94%，4 个连通水域**。

拖一下这个对比滑块——左边原图，右边识别结果，边界贴不贴，评委老师一眼能看出来。"

**关键动作**：拖动对比滑块 2 秒，让评委看到边界贴合度。

## 0:50–1:25 双时相：回答"新增了多少"（差异化亮点）

**操作**：切到页签②，同样选 **【真实】鄱阳湖 2020**，点击 **🔍 开始对比**。

**说**：
"只看一景，只能知道'淹了多少'。但应急指挥部真正要问的是：**这场洪水之后，新增淹没了多少？哪些地方退水了？**

我们把灾前、灾后两景真实影像一起送进模型，自动算出三张图：红色是新增淹没，绿色是退水，青色是持续水体。这一次：灾前 44 平方公里 → 灾后 154 平方公里，**新增淹没 111 平方公里**——和公开灾情报道的量级完全对得上。

这就是可以直接写进应急简报的数字。"

从'看到图'到'能上报'，中间不需要人工再整理。"

## 1:50–2:30 技术底牌（讲清"为什么不是调个阈值"）

**操作**：切到页签③，或展示 README 架构图。

**说**：
"技术上有三个点想请评委关注：

**第一，双模型策略。** NDWI + Otsu 基线不依赖 GPU 和训练数据，第一天就能用，作为对照组；U-Net 语义分割负责精度上限。评委如果问'凭什么比传统方法好'，我们有基线可对比。

**第二，一个物理先验带来的精度提升。** 纯 NDWI 最大的假阳性来源是城市——屋顶在绿-近红外指数上和浅水很像。我们加了一道**近红外物理闸门**：水体近红外反射率极低，城市很高。就这一条，把验证集平均 IoU 从 0.83 提到 0.92，精确率从 0.87 提到 0.98。

**第三，真实数据的工程严谨性。** 刚才演示的两景是真实 Sentinel-2 L2A 影像。抓取过程中我们发现并解决了一个会**直接毁掉 NDWI** 的坑：2022 年后 ESA 的 L2A 产品带 −1000 的 BOA 偏移，而公开数据源有的已扣、有的没扣，连官方 STAC 的标记都存在已知错误。我们的做法是与**原始 JP2 逐窗比对**——同一窗口 COG 与 JP2 的中位 DN 差恰好 −1000，才判定已扣偏移。

还有一件事必须坦白：我们试过 2024 年洞庭湖团洲垸决口，但那个时段 AOI 窗口云量最低的一景仍有 33.5% 被云遮挡——**洪水来了，云也来了**。这正是我们下一步要接入 Sentinel-1 雷达的原因。"

**注意**：讲数字时明确说"这是**合成演示数据**上的验证结果；真实影像我们做了量级合理性交叉验证，但**真实精度必须用 Sen1Floods11 训练后重新评测**"。**不要编造真实数据精度**——评委追问一句就穿帮。

## 附：评委高频问题准备

| 问题 | 回答要点 |
|---|---|
| 演示的是真实卫星影像吗？ | 是。`data/real/` 两组真实 Sentinel-2 L2A 影像（鄱阳湖 2020、涿州 2023），景号、成像时间、AOI 窗口云量、坐标系、偏移量处理方式全部记录在 `samples.json`，可逐条复核。 |
| 为什么没有 2024 年洞庭湖？ | 试过了，抓不到：2024-07-06~07-25 期间 AOI 窗口云量最低的一景仍有 33.5% 被云遮挡（最差 99.9%），脚本按阈值拒绝出图。这是光学遥感的固有短板，也是我们下一步接 Sentinel-1 雷达的直接原因。 |
| 和现成的遥感软件（ENVI、GEE）有什么区别？ | GEE 给的是指数和工具，我们给的是"**端到端的面积结论 + 可上报简报**"；且模型可离线部署在应急内网。 |
| 云怎么办？ | 云遮挡是光学遥感的固有短板。短期：用 Sentinel-1 雷达做补充；长期：把云检测作为独立分支。已在 Roadmap 中。 |
| 精度多少？ | 合成数据上 U-Net IoU 0.97、基线 0.92；真实影像**只做了量级合理性交叉验证**（鄱阳湖新增淹没 111 km²、涿州 3.98 km²，与公开灾情报道量级一致），**没有逐像元真值就不能谈精度**。Sen1Floods11 训练评测是下一阶段目标。 |
| 合成数据训练的模型能直接用吗？ | 不能。我们实测过：大水体上还行（155 vs 154 km²），小尺度城区洪水明显过检（12.17 vs 5.26 km²）。系统会自动提示，这正是必须用真实数据训练的实证。 |
| 为什么用 U-Net 不用 Transformer？ | U-Net + 预训练骨干在中小数据集上更稳、参数少、推理快，适合应急场景的实时性要求；Transformer 方案已列入对比实验。 |
| 数据从哪来、合法吗？ | Sentinel-2 是欧空局免费公开数据，Sen1Floods11 是公开学术数据集，均可商用/科研使用。 |
| 商业价值在哪？ | 应急管理部门的灾害评估、自然资源部门的国土监测、保险公司的农险/财产险快速定损。 |
| 团队怎么分工？ | （按实际填写）算法/前端/数据/答辩各 1 人，已形成每周迭代机制。 |
