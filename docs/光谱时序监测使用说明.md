# 本地多时相光谱监测

`python scripts/run_spectral.py` 可把按时间顺序排列的本地多景 GeoTIFF 自动配准到首景网格，计算每期指数和相邻两期差值，并写出带 CRS 的 GIS 栅格与 `summary.json`。此流程独立于洪水识别与批量任务库，不联网，也不会自动核验影像的观测日期。

## 适用方向

| 指数 | 所需波段 | 用途与边界 |
|---|---|---|
| NDVI | 红、近红外 | 植被绿度及相邻时相变化；下降不等于已确认的病害或灾损。 |
| SAVI（L=0.5） | 红、近红外 | 在植被稀疏、土壤背景影响较大区域观察绿度变化。 |
| NDWI（绿光/近红外） | 绿、近红外 | 地表水光谱指数的连续观测；指数变化不等于已确认的淹没面积。 |
| MNDWI | 绿、SWIR1（B11） | 用 SWIR 抑制建筑/土壤背景的水体指数，观察地表水变化；变化不等于淹没面积。 |
| NDMI | 近红外、SWIR1（B11） | 冠层含水量的相对指示，观察植被水分时序变化；不等同于实测含水量。 |
| NBR | 近红外、SWIR2（B12） | 植被与火烧敏感指数；只报告指数及其相邻差值，不给火烧等级。 |

公式分别为 `(NIR−Red)/(NIR+Red)`、`1.5×(NIR−Red)/(NIR+Red+0.5)`、`(Green−NIR)/(Green+NIR)`、`(Green−SWIR1)/(Green+SWIR1)`、`(NIR−SWIR1)/(NIR+SWIR1)`、`(NIR−SWIR2)/(NIR+SWIR2)`。NDVI/SAVI/NDWI 只用项目已有的四波段数据；MNDWI/NDMI/NBR **依赖真实 SWIR 反射率**（Sentinel-2 的 B11、B12），四波段影像无法计算，缺少真实 SWIR 时程序直接报错，不会用其他波段替代。

## SWIR 输入与分辨率边界

- MNDWI/NDMI/NBR 必须使用真实 SWIR 波段。可用 `--band-order s2_6band` 显式声明 `B2 B3 B4 B8 B11 B12` 的顺序，或提供可识别的波段描述（`B11`/`swir1`、`B12`/`swir2`）。`auto` 不会仅凭通道数猜测 SWIR；无描述的六波段影像需要显式预设。
- Sentinel-2 的 B11/B12 原始分辨率为 20 m，B2/B3/B4/B8 为 10 m。本项目**不改变在线四波段下载流程**，SWIR 需另行准备；把 20 m 的 SWIR 重采样到 10 m 只是与 10 m 波段同网格，**不会提升其真实空间分辨率**，混合像元与配准误差依旧存在。
- 不同分辨率或不同处理级别的影像即使完成空间配准，也不能直接视为可比；跨传感器、跨季节比较需另行评估。

## 运行

从项目根目录执行（按影像真实拍摄时间排列）。下面使用仓库的合成演示影像，只用于检查流程：

```powershell
python scripts/run_spectral.py --index ndvi --images data/samples/demo01_pre.tif data/samples/demo01_post.tif --out-dir outputs/spectral_demo --min-valid-pct 50
```

若已有含真实 SWIR 的六波段影像，可改用 SWIR 指数（须显式声明波段顺序）：

```powershell
python scripts/run_spectral.py --index ndmi --band-order s2_6band --images pre.tif post.tif --out-dir outputs/ndmi_demo --min-valid-pct 50
```

若观测日期已由用户核对，可加 `--dates 2020-05-19 2020-07-15`，数量必须与影像数量一致且严格递增。未提供时摘要中的日期为 `null`，系统不会从文件名推断。指定日期只是用户声明，软件不会与卫星元数据交叉验证。三景或更多景会给出逐期指数和相邻两期差值；首景是固定参考网格。可通过 `--index savi`、`--index ndwi`、`--index mndwi`、`--index ndmi`、`--index nbr` 更换配方。每次显式指定的 `--out-dir` 必须是新目录，防止覆盖旧成果；省略此参数时程序自动建立唯一输出目录。

输入须有真实 CRS、仿射变换和所需波段。默认沿用 `src.preprocess.load_scene` 的波段描述解析及四波段 B2/B3/B4/B8 顺序；SWIR 指数可用 `--band-order s2_6band`（B2 B3 B4 B8 B11 B12），其他顺序应提供正确描述或显式预设。不同传感器或处理级别的影像不能仅靠空间配准就视为可直接比较。

网页底部的“多时相遥感监测”支持同一流程和成果包下载。Gradio 上传不包含同名 SCL 侧车；如需应用完整侧车质量层，使用本地命令行并保留侧车在输入影像旁。

## 质量与成果口径

- 每景指数 GeoTIFF 和相邻差值 GeoTIFF 使用 `float32`，`-9999` 表示无效；`0` 是合法指数值或零差值。
- 相邻两景的共同有效区 GeoTIFF 使用 `uint8`：`1=共同有效`、`0=无效`，`0` 不是 NoData。差值只在共同有效像元上计算。
- 存在同名 `_scl.tif` / `_scl.tiff` / `_scl.png` 时，剔除 SCL 0、1、3、8、9、10、11 类；没有 SCL 时会警告云、云影、雪及缺陷像元未完成筛除。GeoTIFF 侧车必须与主影像网格和 CRS 完全一致；PNG 只有尺寸可核对，需人工确认像素位置。摘要记录侧车路径与哈希。
- 单景或相邻两景共同有效比例低于 `--min-valid-pct` 时，统计值写成 JSON `null`，相邻差值栅格全为 NoData，不会报成零。摘要同时列出输入文件哈希、参数和质量原因。每景均值使用各自有效区；跨期变化请看仅使用共同有效区的相邻差值。
- 面积仅在米制投影且网格像元面积可计算时给出。指数差值是连续量；面积字段描述的是共同可观测范围，不代表植被损失或新增水域范围。
- **差值方向**：所有指数的相邻差值统一为“后一时相 − 前一时相”（后减前）。NBR 的相邻差值**不是传统 dNBR**——传统 dNBR 通常为“火前 − 火后”（前减后），与本工具符号相反，因此不得把本差值当作 dNBR 或套用 dNBR 分级阈值。本工具只输出连续指数与相邻差值，**不提供火烧等级/严重度分级，也不提供干旱面积**；这些分级结论需要现场或独立真值支撑，超出本工具范围。
- 单个必需波段出现 NoData（如仅 B11 缺失）时，该像元整体判为无效，不参与均值与相邻差值，避免 SWIR 缺测被误读成指数变化。

结果位于 `--out-dir`，其中 `summary.json` 是本次解释统计的入口。演示影像为合成数据，不支持真实精度声明；实际业务还需控制季节差异、传感器差异、云影与地形阴影，并结合现场或独立真值核验。

公式参考：[USGS NDVI](https://www.usgs.gov/landsat-missions/landsat-normalized-difference-vegetation-index)、[USGS SAVI](https://www.usgs.gov/landsat-missions/landsat-soil-adjusted-vegetation-index)、[USGS HLS 光谱指数说明](https://lpdaac.usgs.gov/documents/2088/HLS_VI_User_Guide_V2.pdf)。
