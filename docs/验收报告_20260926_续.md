## 二、本轮修改

### 1. 冻结 EXE 启动阻塞：从"根因未确认"到可复现结论

**结论**：本机 Windows 防火墙入站策略为 `BlockInbound,AllowOutbound`。未被放行的可执行文件即使只监听 `127.0.0.1`，发往它的连接也会被**静默丢弃**（表现为连接超时，而非被拒绝）。CPython 在 Windows 上用一对回环 TCP 连接模拟 `socket.socketpair()`，该调用没有超时；连接被丢弃后 `asyncio` 在建事件循环时永久阻塞，界面永远起不来。

四组对照实验（`outputs/release_v0.5.0/`）：

| 实验 | 源码 `python.exe` | 打包 EXE |
|---|---|---|
| 进程内 `bind→listen→connect`（`net_compare.json`） | 0.002 秒成功 | 4 秒超时 |
| 外部进程连接其监听端口（`net_serve_compare.json`） | 成功 | 超时 |
| 反向：本进程连外部监听端口（`net_compare.json`） | 成功 | 成功 |
| 被冻结的 `socket.socketpair()` | 成功 | **永久挂起（>8 秒无返回）** |

关键判别实验：把 `python.exe` **原样复制改名**为 `python_probe_copy.exe`，字节完全相同、目录相同、仅文件名不同——行为从"0.002 秒成功"变成"超时 + `socketpair` 挂起"。因此过滤按**可执行文件身份**生效，与 PyInstaller、与项目代码都无关。剥离代理变量、关闭本工具的沙箱隔离，结果均不变。

**代码改动**（`app/desktop.py`）：

- 新增 `LoopbackError`（继承 `OSError`，兼容既有 `except OSError` 调用方），携带 `stage` / `cause` / `detail` / `remedy`。
- `check_loopback()` 改为分阶段探针，精确指出失败发生在 `bind` / `listen` / `connect` / `accept` / `recv` 哪一步。
- 新增 `classify_loopback_failure()`：把"连接超时"判为 `inbound_filtered`（入站过滤，给放行命令），把"连接被拒绝"判为 `not_listening`（程序自身问题，**不**诱导用户去改防火墙），另有 `bind_denied` 与 `unknown`。
- 新增 `firewall_remedy()`：生成 `netsh advfirewall firewall add rule … dir=in action=allow protocol=TCP program="<本程序>" profile=any`，只放行这一个文件、只放行 TCP。
- 新增 `loopback_failure_message()`：启动失败时输出判定结论 + 可直接粘贴的命令 + 脚本指引。
- `--diagnose` 报告新增 `executable` 与 `loopback.{stage,cause,detail,remedy}`。

**新增产物**：`scripts/allow_loopback.ps1`（随包分发到 `_internal/scripts/`）。自行提权、幂等（先删同名旧规则再建）、支持 `-Remove` 撤销、自动定位安装目录下的 `慧眼识灾.exe`。

**注意**：安装包以 `PrivilegesRequired=lowest` 安装、不申请管理员权限，因此**无法在安装阶段自动写防火墙规则**，这一步必须由用户执行一次。本工具以普通用户身份运行（`net session` 判定 `ADMIN=NO`），所以**放行后的冻结界面通过记录需由用户补齐**。

### 2. 安装验收的隔离缺陷（真实缺陷，已修复）

**缺陷**：`build/installer.iss` 设了 `DisableProgramGroupPage=yes`，此时 Inno Setup **会忽略运行期的 `/GROUP=` 参数**，只用编译期的 `DefaultGroupName`。原验收脚本依赖 `/GROUP=` 做隔离，实际却把快捷方式写进了**生产开始菜单组** `慧眼识灾`。证据在 `outputs/release_v0.5.0/install.log`：

```
Setup command line: … /GROUP=HuiYanShiZai Release Smoke 170727 …
Creating directory: C:\Users\21679\AppData\Roaming\…\Start Menu\Programs\慧眼识灾
```

若本机确实装有正式版，该步骤会覆盖并随后删除真实安装的快捷方式。本机 `D:\慧眼识灾\` 已不存在，故未造成实际损坏。

**修复**：

- `build/installer.iss`：新增 `GroupName` 预处理器宏（默认等于 `AppName`），`DefaultGroupName={#GroupName}`，并注明必须用编译期 `/DGroupName=` 而不是运行期 `/GROUP=`。
- `scripts/verify_installer.py` 重写：自行调用 ISCC 编译验收专用安装包（`/DAppIdValue=` + `/DGroupName=`，均带时间戳），不再依赖调用方传入匹配的编译参数。

- 修正 `%APPDATA%` 未导出时的启动菜单路径解析。

### 3. 在线影像下载失败：归因 + 显式降级

**证据**：`online_pipeline.log` 中每一景都报 `RasterioIOError: CURL error: schannel: the revocation status is unknown`；本轮复测（`tls_probe.json`）该主机已变为连接超时（剥代理与否都超时）。即：受限网络访问不到 CRL/OCSP 吊销端点，或根本连不到 S3 COG 主机。

**核查**：反查 GDAL 3.12.1 DLL 中的配置项，只有全关的 `GDAL_HTTP_UNSAFESSL`，**不存在**只关吊销检查的 `CURLSSLOPT_NO_REVOKE` 对应项。因此无法只关吊销。

**改动**（`scripts/fetch_real_samples.py`）：

- 新增 `describe_network_error()`：区分吊销查询失败 / 连接超时 / 域名解析失败；选景全失败时打印根因，而不是只报"N 景被跳过"。
- **判定顺序改为"先 WinError 数字码、再英文关键词"**。这一条是复测时发现的真实缺陷：Windows 系统错误文案会跟随系统语言本地化，本机（中文系统）抛的是
  `URLError: <urlopen error [WinError 10060] 由于连接方在一段时间后没有正确答复…>`，
  只匹配英文 `timed out` 会**全部漏判**。数字码在本地化文案里原样保留，因此以它为准，并额外检查 `URLError.reason` 里的底层异常类型。
- 新增 `allow_unsafe_tls()` + `_gdal_env()` 注入：仅当显式设 `FLOOD_ALLOW_UNSAFE_TLS=1` 时才置 `GDAL_HTTP_UNSAFESSL=YES`，默认保持证书校验。
- 新增 `provenance_common()`：把 `tls_verification_disabled` 写入成果溯源，降级必须留痕。
- STAC 检索失败也会打印归因（此前只打原始异常）。

**复测**（`online_recheck.json`）：本轮网络下连 STAC 目录主机也直接超时，剥代理与否都一样，在线链路**端到端仍无法验证**；但归因链路已生效，输出 `连接超时：目标主机不可达或被拦截，请检查网络与代理设置后重试。`，且对纯网络不通**不会**建议关闭证书校验。

### 5. 测试收集缺陷（清理残留时暴露，已修复）

**这是本轮清理动作的副产品，也是一个真实缺陷。**

`net_serve_test.py` 是本轮为定位回环问题写的**调查脚本**（顶层可执行代码，没有任何 `def test_`），放在 `outputs/release_v0.5.0/` 下。仓库没有 pytest 配置文件，而文档记录的验收命令是 `python -m pytest -q`（在仓库根执行），于是 pytest 按默认规则递归收集，把 `*_test.py` 也当测试**导入**——导入即执行顶层代码，**在收集阶段就启动探针进程并等待端口文件**。

后果有两层：

1. **一直存在的隐性开销**：该脚本在收集期等待探针、对外连接超时 6 秒、再跑一遍源码对照，实测让整轮测试从 ~31 秒变成 ~47 秒。此前没人注意到，因为它是"静默多花时间"而非报错。
2. **清理后直接中断**：本轮删掉 `outputs/release_v0.5.0/probe_net/` 后，脚本在导入时 `subprocess.Popen` 找不到 `net_probe.exe`，抛 `FileNotFoundError`，pytest 报 `Interrupted: 1 error during collection`，**整套测试一个都跑不了**。

**修复**：新增 `pytest.ini`，用 `norecursedirs` 明确排除产物目录（`outputs`、`dist*`、`build`、`node_modules` 等）。之所以把默认项（`.*`、`build`、`dist`、`*.egg`、`venv` 等）一并显式写出，是因为**设置 `norecursedirs` 会覆盖 pytest 默认值**，漏写反而会把 `dist/` 里的第三方包扫进来。

**效果**：测试项数不变（**305 通过 / 7 跳过**，证明这 305 项本来就全部来自 `tests/` 与根目录的 `test_e2e.py`），耗时从 **47.23s 降到 30.83s**，且 `outputs/` 下的调查脚本不再被收集。
